# Roadmap

This roadmap covers two things, kept clearly separate: **milestones that are actually implemented** (verified against the codebase and the project's own milestone-tracking documents in `.ai/`), and **future work** that has been discussed but does not exist in code yet. Nothing in the "Future Roadmap" section should be read as implemented.

> **Source note:** Milestones M1–M13 are cross-referenced against `.ai/CURRENT_STATE.md` and `.ai/ENTERPRISE_ROADMAP.md`, the project's own running milestone logs. ## Test Suite Growth

The milestone-by-milestone test count (from project history and this session) is a useful proxy for how seriously each milestone was verified before being called complete: M12 completed at 128 tests; M13 (through embedding infrastructure) built on that; the AI Operating System milestones added 128 (Executive), 187 (Tools), 207 (Specialists/Research), and 232 (Vision) tests respectively; **2016** passing at the M19 completion pass; **2029** after M20.1's architecture enforcement suite and M20.5's registry consolidation; **2044** after M20.6's `AgentMemory` implementation — the count as of the M20.7 architecture freeze; **2197** after CP-01.2's Personal Intelligence Pack implementation (156 new tests: 146 for the new pack, 10 for `MemoryAdapter`'s completed `remember()`/`forget()`); **2368** after CP-01.3's Insight Engine (171 new tests). Zero regressions tolerated at any step, the whole way through.

## From Milestones to Capability Packs (Post-M20.7)

M20.7 is the **last** architecture milestone. As of this freeze, the AI Operating System's core (`shared/`, `kernel/`, `runtime/`, `conversation/`, `agents/` — the framework itself, `tools/`, `vision/`) is locked at version 1.0: future work builds on top of it through the documented extension points, never by modifying it (see [ARCHITECTURE_FREEZE_v1.md](../ARCHITECTURE_FREEZE_v1.md)'s Future Development Rules). Work from here forward is tracked as **Capability Packs (CP-NN)**, not milestones (M-NN) — see [Capability_Strategy.md](../08_CAPABILITY_PACKS/Capability_Strategy.md) for the full strategy and the CP-01 through CP-07 sequence.

## Future Roadmap

The items below are **not implemented**. They are documented here as the platform's stated direction, gathered from this sprint's brief and the project's own longer-range planning documents (`.ai/ROADMAP.md`, `.ai/ENTERPRISE_ROADMAP.md`). Post-M20.7, most of what follows is realized as a **Capability Pack** (see [Capability_Strategy.md](../08_CAPABILITY_PACKS/Capability_Strategy.md)) rather than a numbered milestone — each bullet below maps onto one or more packs in that document's CP-01 through CP-07 sequence.

### Near-term: more specialists and capabilities
- **Learning Agent** — a specialist analogous to `ResearchAgent`, for structured study/learning workflows. Would follow the exact `SpecialistAgent` extension pattern documented in [Adding_Agent.md](../06_DEVELOPMENT/Adding_Agent.md).
- **Product Management Intelligence Pack (CP-02)** — **Version 1 complete and frozen.** Discovery, Product Decision, Delivery, Strategy & Portfolio, and Stakeholder Communication specialists for product-management workflows (roadmapping, spec drafting, prioritization). All ten implementation milestones complete ([PRD.md](../08_CAPABILITY_PACKS/CP-02_Product_Management_Intelligence_Pack/PRD.md), [Architecture.md](../08_CAPABILITY_PACKS/CP-02_Product_Management_Intelligence_Pack/Architecture.md), [ARR.md](../08_CAPABILITY_PACKS/CP-02_Product_Management_Intelligence_Pack/ARR.md), [Implementation_Plan.md](../08_CAPABILITY_PACKS/CP-02_Product_Management_Intelligence_Pack/Implementation_Plan.md), [Production Readiness Report](../08_CAPABILITY_PACKS/CP-02_Product_Management_Intelligence_Pack/Production_Readiness_Report.md), [Release Candidate record](../08_CAPABILITY_PACKS/CP-02_Product_Management_Intelligence_Pack/CP-02_RELEASE_CANDIDATE.md)). All five specialists implemented, integration-validated against the Executive, and fully documented ([Capability Guide](../04_CAPABILITIES/Product_Management_Intelligence.md), [Developer Guide](../06_DEVELOPMENT/Adding_Product_Management_Specialists.md), five per-specialist agent guides under `docs/05_AGENTS/`). 3,134 tests passing platform-wide, zero regressions across all ten milestones. No further architectural work against this version — only maintenance and bug fixes; future enhancements occur through Version 2 or a future Capability Pack built on top of CP-02. A "Career Intelligence" pack has been named as the next major initiative — see the note above on why it isn't assigned a CP number here (CP-03 through CP-08 are already reserved for other packs).
- **Finance Agent** — a specialist for financial analysis/planning workflows; the natural home for the personal-finance and enterprise-finance use cases described in [Vision.md](Vision.md).
- **Business Architect** — a higher-level specialist or orchestration role for business-process design, likely consuming multiple other specialists.
- **Audio Framework** — a shared OS capability for audio understanding (transcription, speaker diarization, audio classification), expected to mirror the Vision Framework's exact shape (`Agent → Audio Framework → Audio Provider → Implementation`).
- **Speech Framework** — a shared OS capability for speech synthesis/recognition, likely distinct from the Audio Framework (understanding vs. generation), following the same provider-agnostic pattern.

### Mid-term: platform maturity
- **Knowledge Governance** — document lifecycle, retention policies, versioning, and approval workflows for the Knowledge Engine (M12). This was the originally planned M14 in `.ai/ENTERPRISE_ROADMAP.md`; it has not yet been built and is still open.
- **Organization Operating Systems** — coordinated multi-specialist workflows for running actual business functions (CRM, sales, marketing, procurement, reporting) — corresponds to Phase 5 ("Business Operating System") and Phase 6 ("Real Estate Operating System") of `.ai/ROADMAP.md`'s longer-range plan. Depends on the Executive/Specialist/Tool frameworks already in place, plus a broader tool catalog than exists today.
- **Self-improving AI** — agents that can evaluate and refine their own plans, tools, or prompts over time. No self-modification or learning-loop mechanism exists anywhere in the current platform; every planner today (`ExecutivePlanner`, `SpecialistPlanner`, `ResearchPlanner`) is deterministic and template-based, not adaptive.

### Long-term: production and reach
- **Enterprise Deployment** — production-grade deployment, monitoring, scaling, resilience, and audit readiness, corresponding to Phase 10 of `.ai/ROADMAP.md`. No deployment-specific infrastructure (beyond the existing Docker setup) currently exists in this repository.

## Known Discrepancy: Planning Documents vs. Implementation

`.ai/ENTERPRISE_ROADMAP.md` and `.ai/CURRENT_STATE.md` currently project **M14 — Knowledge Governance** as the next milestone after M13. That is not what was actually built next: engineering instead pivoted to building the AI Operating System itself (AI Platform → Kernel → Runtime → Agent Framework → Executive → Tools → Specialists → Vision, M16 through M19). This is a real, current inconsistency between the project's own planning documents and its implementation history, not an error in this documentation — it is called out explicitly here, and in the ADS-1 sprint summary, so it can be deliberately reconciled (by updating `.ai/ENTERPRISE_ROADMAP.md`, or by treating the AI Operating System work as a deliberately-approved scope change) rather than silently papered over.
